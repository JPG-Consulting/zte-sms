# ZTE MF833U1 — observed HTTP API

**Evidence level:** locally verified through Chrome Developer Tools and Postman on one MF833U1. Other firmware versions may differ. This is not an official ZTE API specification.

## Base URL

`http://192.168.0.1`

The modem SMS UI was observed at `/index.html#sms`.

## Read stored SMS (verified)

```http
GET /goform/goform_get_cmd_process?isTest=false&cmd=sms_data_total&page=0&data_per_page=500&mem_store=1&tags=10&order_by=order+by+id+desc HTTP/1.1
Host: 192.168.0.1
Referer: http://192.168.0.1/index.html
```

In Postman, this returned a `messages` array containing a received SMS. The **same request without `Referer` returned** `{"sms_data_total":""}`. Browser `fetch` within the modem UI also succeeded without explicitly setting `X-Requested-With`; therefore that header is **not established as necessary**. A timestamp-like `_` query parameter appeared in browser requests but was not required in the successful Postman test.

**Important:** The effect of `Referer` was observed, not a proof that no other conditions apply (firmware/session behavior may vary). Do not assume this API is authenticated or safe to expose outside the trusted LAN.

### Sanitized response shape

```json
{
  "messages": [
    {
      "id": "3",
      "number": "+34000000000",
      "content": "005000720075006500620061",
      "tag": "1",
      "date": "26,10,24,15,06,16,+8",
      "draft_group_id": "",
      "received_all_concat_sms": "1",
      "concat_sms_total": "0",
      "concat_sms_received": "0",
      "sms_class": "4"
    }
  ]
}
```

The `content` example is synthetic and decodes to `Prueba`. The sample phone number is a placeholder. The exact semantics of `tag`, `mem_store`, `tags`, and date timezone suffix have **not been established**. Do not hard-code assumptions about them.

### Encoding

`content` consists of hexadecimal UTF-16 big-endian code units (e.g. `0050 0072 0075 0065 0062 0061` -> `Prueba`). Handle malformed input and surrogate pairs; don't assume plain ASCII.

## Multiple state fields (verified)

```http
GET /goform/goform_get_cmd_process?multi_data=1&isTest=false&cmd=modem_main_state%2Cpin_status%2Cnetwork_type HTTP/1.1
```

In the browser console, this returned separate values such as `modem_init_complete`, `0`, and `LTE`. Without `multi_data=1`, the comma-separated command string was interpreted as one field. This behavior is separate from the SMS-list endpoint, which worked without `multi_data=1`.

## Unresolved commands

- `sms_received_flag` and `sms_db_change` returned empty strings during an idle test; their precise semantics are unknown.
- `sms_capacity_info` returned an empty string in an initial direct test.
- `sms_data_total` with only `cmd` (no pagination/filter parameters) returned an empty string.
- **SMS send API: not yet captured or tested.**
- Deletion, marking read, pagination beyond the first page, multipart SMS, Unicode edge cases, polling interval, and device authentication are unverified.

## Safe reproduction

From a trusted local host with modem reachability, use a GET with the Referer header. Responses may contain personal information: inspect locally, do not post unredacted JSON. Never send credentials or tokens to a third-party service.
