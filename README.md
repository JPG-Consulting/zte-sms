# ZTE SMS for Home Assistant

A custom Home Assistant integration for sending SMS messages through compatible ZTE LTE modems using their local HTTP interface.

Initial development and testing target the **ZTE MF833U1**.

> **Project status: early development (v0.1.0).**
>
> SMS sending has been successfully tested on a ZTE MF833U1 from Home Assistant, including Unicode characters and the notification entity. The integration is not yet considered production-ready. Compatibility with other models and firmware versions has not been verified.

## Features

### Implemented

- Configuration through the Home Assistant user interface.
- Configurable modem IP address or hostname.
- Multiple default SMS recipients, configurable during setup or through integration options.
- `zte_sms.send_sms` action for sending a message to one explicitly specified phone number.
- `notify.zte_sms` notification entity for sending a message separately to each configured default recipient.
- UTF-16BE message encoding with `UNICODE` mode, successfully tested with Spanish accented characters and `ñ`.

### Not yet implemented

- Automatic cleanup of integration-generated sent SMS.
- SMS storage-capacity monitoring.
- Incoming SMS entities, events, or automation triggers.
- Local SMS archiving, message viewer, or synchronization.
- Cellular signal or network-status monitoring.
- Independently verified SMS delivery confirmation.
- Comprehensive error reporting and privacy-safe diagnostic logging.

**The integration does not currently poll the SMS inbox, delete messages, or modify modem or router settings.**

## First stable-release milestone

The immediate development priority is **fast, robust outbound SMS sending and safe management of sent-message storage on the modem**.

Before the first stable release, the project aims to:

- Improve error handling and distinguish confirmed failures from uncertain submission outcomes.
- Avoid automatic retries that could produce duplicate SMS.
- Investigate whether SMS generated by the integration occupy modem storage.
- Verify whether those stored messages can be identified and deleted safely.
- Implement post-submission cleanup only if reliable message ownership and deletion semantics can be established.
- Provide a user option to retain integration-generated messages in modem storage if safe cleanup is implemented.
- Complete the relevant automated and authorized real-device tests.

**Sending takes priority.** An SMS submission must not wait for inbox synchronization, cellular status checks, local archive writes, or stored-message cleanup.

Automatic deletion must never affect received SMS, manually sent SMS, or messages whose origin cannot be proven.

If safe cleanup cannot be verified, the integration must not attempt speculative deletion or claim to prevent storage exhaustion. The limitation must be addressed before the milestone can be considered complete.

Local archiving, a message viewer, synchronization, incoming SMS features, and optional LTE monitoring are planned for later milestones, after the first stable release is validated and merged into `main`.

## Requirements

- Home Assistant with support for custom integrations and notification entities.
- A ZTE modem accessible through its local HTTP interface.
- A working SIM card and SMS service.
- Network connectivity from Home Assistant to the modem.

The ZTE MF833U1 is the initial tested device. Other ZTE models are not automatically considered compatible.

See [Compatibility](docs/compatibility.md) for device-specific information.

## Installation

### Manual installation

1. Download the repository.
2. Copy `custom_components/zte_sms` into the `custom_components` directory of your Home Assistant configuration.
3. Restart Home Assistant.
4. Navigate to **Settings → Devices & services → Add integration**.
5. Search for **ZTE SMS**.
6. Enter the modem host or IP address and, optionally, one or more default SMS recipients.

The default modem address is `192.168.0.1`.

### Configuration

Default recipients must use international phone-number format, beginning with `+` followed by digits.

You can update the recipient list through the integration's **Options**.

## Sending SMS

### Send to a specific recipient

In Home Assistant, run the action `zte_sms.send_sms`:

```yaml
action: zte_sms.send_sms
data:
  number: "+34000000000"
  message: "Test message from Home Assistant"
```

This action currently accepts **one recipient per call**.

### Send using the notification entity

Configure one or more default recipients in the integration, then run:

```yaml
action: notify.send_message
target:
  entity_id: notify.zte_sms
data:
  message: "Alarm notification from Home Assistant"
```

The notification entity sends an individual SMS to each configured default recipient.

A successful response from the modem means that the modem accepted the sending request. It does **not** independently prove delivery to the recipient.

**SMS sending may incur charges according to your mobile operator and plan.**

## Safety and privacy

This integration must not interfere with the modem's existing LTE Internet connection or any router failover configuration.

In particular:

- Do not change the modem's firmware, USB mode, APN, or network settings as part of SMS development.
- Never delete received, manually sent, or otherwise unidentifiable SMS automatically.
- Do not introduce automatic inbox polling without explicit opt-in.
- Never log SMS bodies, full phone numbers, credentials, cookies, or authentication tokens.
- Do not expose the modem's management interface to the public Internet.
- Live SMS sending or other state-changing operations must not occur in automated tests.

Future optional polling, synchronization, and local archiving must remain independent of the critical SMS submission path.

## Development and testing

The integration source code is located in `custom_components/zte_sms`.

Automated tests are located in `tests/`. Run them with:

```bash
python -m unittest discover -s tests -v
```

GitHub Actions provides automated checks. Passing these checks does not replace testing inside Home Assistant or against supported hardware.

The project is preparing a `main` / `develop` branching workflow. Until that workflow is established, `main` remains the current working branch.
