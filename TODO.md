# TODO — ZTE SMS

This file tracks actionable work for the ZTE SMS Home Assistant integration.

It is the project's primary task list. Experimental findings belong in [docs/research-log.md](docs/research-log.md), and verified modem API behavior belongs in [docs/api/mf833u1.md](docs/api/mf833u1.md).

## Working principles

- Keep `main` stable and follow the documented development workflow once established.
- Make small, independently reviewable changes.
- Prioritize fast, reliable outbound SMS submission over additional features.
- Never disrupt the MikroTik LTE Internet fallback or modify modem network settings.
- Never send real SMS during automated tests.
- Never delete messages without verified integration ownership and an exact modem message identifier.
- Never delete received messages or manually sent messages as part of integration cleanup.
- Do not require inbox synchronization, signal checks, archive writes, or cleanup before sending an SMS.
- Keep optional periodic polling disabled by default.
- Allow future on-demand queries without requiring polling.
- Never expose SMS contents, complete phone numbers, credentials, cookies, or tokens in logs.
- Do not claim delivery confirmation based solely on modem API acceptance.
- Do not automatically retry uncertain SMS submissions.

## Milestone 1 — Reliable outbound SMS and safe sent-message cleanup

**Goal:** deliver fast, robust outbound SMS sending and safely manage the modem storage occupied by messages generated by this integration.

This is the first stable-release milestone. It must be completed and validated before expanding the integration with message synchronization, local archiving, or monitoring.

### Release requirements

- [ ] Validate SMS submission reliability, including relevant failure scenarios.
- [ ] Keep the SMS submission path independent of nonessential modem queries and maintenance operations.
- [ ] Distinguish confirmed failures, modem acceptance, and uncertain submission outcomes.
- [ ] Prevent automatic retries that could duplicate an SMS.
- [ ] Verify Home Assistant action and notification behavior.
- [ ] Provide privacy-safe diagnostics and predictable error reporting.
- [ ] Determine whether integration-generated outbound SMS consume modem storage.
- [ ] Investigate safe identification and deletion of integration-generated stored SMS.
- [ ] Implement safe sent-message cleanup only if its safety requirements can be verified.
- [ ] Provide a user-controlled option to retain integration-generated sent messages in modem storage if cleanup is supported.
- [ ] Document and resolve any limitation that prevents safe storage management before declaring the milestone complete.
- [ ] Complete relevant automated tests and explicitly authorized real-device tests.
- [ ] Verify that the integration does not alter LTE failover behavior or introduce unsolicited polling.
- [ ] Update documentation and publish a validated release through the established Git workflow.

**Critical-path rule:** outbound SMS submission must not wait for inbox synchronization, cellular status checks, local archive writes, or stored-message cleanup.

Cleanup is a separate post-submission operation. Its failure must be reported or recorded appropriately without automatically resending the SMS.

### Safe deletion requirements

All conditions below must be satisfied before enabling automatic deletion:

- [ ] Prove that the stored message was created by this integration.
- [ ] Obtain the exact modem identifier of the stored message.
- [ ] Verify that the identifier remains reliable across relevant modem operations.
- [ ] Verify that deletion cannot affect received or manually sent messages.
- [ ] Verify that deletion cannot interfere with a pending SMS submission or transmission.
- [ ] Test repeated messages, concurrent sends, failures, and ambiguous responses.
- [ ] Verify the behavior of the user option to retain messages in the modem.

Matching a phone number, message body, timestamp, or sent-folder location is not sufficient proof of ownership.

**If safe deletion cannot be established, automatic deletion is prohibited.** Investigate a safe alternative and document the limitation. Do not claim that modem storage exhaustion has been prevented without evidence.

## Later milestone — Optional periodic monitoring

Periodic monitoring detects changes by repeatedly querying the modem. It must remain independent of on-demand queries and disabled by default.

- [ ] Investigate modem reachability, cellular registration, and signal measurements.
- [ ] Design optional Home Assistant monitoring entities.
- [ ] Provide a configurable polling interval.
- [ ] Allow monitoring to be enabled and disabled through supported Home Assistant controls.
- [ ] Investigate temporary activation through automations such as Alarmo.
- [ ] Define interactions between manual preferences and temporary automation requests.
- [ ] Ensure monitoring does not block outbound SMS submission.
- [ ] Document request frequency, network traffic, and unreachable-modem behavior.

Modem reachability, cellular registration, signal strength, and SMS delivery are different conditions. Signal loss alone is not proof of deliberate interference.

## Maintenance rules

When completing a task:

1. Verify the result using appropriate automated or authorized manual tests.
2. Mark the item as completed with `[x]`.
3. Update documentation if behavior or compatibility changed.
4. Record new evidence in the research log or API documentation.
5. Remove obsolete or duplicated tasks when appropriate.

### Priority definitions

- **P0:** Project organization and release readiness.
- **P1:** Milestone 1 reliability, privacy, testing, and safe storage management.
- **Later milestones:** Features that must not delay the first stable release.

Safety requirements take precedence over feature priority.
